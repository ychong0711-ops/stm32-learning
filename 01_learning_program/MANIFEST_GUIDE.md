# manifest.json — 프로젝트 번들 포맷 가이드

> 이 학습 프로그램을 **다른 STM32F4·FreeRTOS·C 프로젝트**에 적용하기 위한 번들 포맷입니다.
> "📦 프로젝트" 탭에서 이 JSON 을 로드하면 파일·학습 경로·퀴즈·미션·RTA 태스크가 모두 교체됩니다.

---

## 1. 전체 스키마

```json
{
  "title": "프로젝트명 (선택)",
  "files":    [ { "path": "src/x.c", "content": "...소스 전문..." } ],
  "notes":    { "src/x.c": "파일 설명 (선택)" },
  "path":     [ 모듈, ... ],      // 학습 경로
  "quiz":     [ 객관식, ... ],     // 4지선다
  "subquiz":  [ 주관식, ... ],     // 회상형 (정답 동의어 허용)
  "missions": [ 미션, ... ],       // 빈칸 채우기
  "rta":      [ 태스크, ... ]      // 응답시간 분석용 태스크셋
  "schedTasks": [ 태스크, ... ]    // 스케줄러 시뮬레이터 태스크셋 (선택)
  "lastProgress": { ... }          // 이전 번들에서의 진행도 (선택, 자동 보존)
}
```

모든 필드는 선택입니다. `files` 만 넣으면 파일 브라우저만 교체되고, 나머지는 기존 유지됩니다.

---

## 2. 각 필드 상세

### files — 교재 소스
```json
{ "path": "src/temp_alarm.c", "content": "// 주석 포함 전체 소스\n..." }
```
- `path`: 코드 학습 탭 드롭다운에 표시되는 경로
- `content`: 전체 소스 텍스트. **전 줄 한글 주석을 권장**합니다 (이 프로그램의 학습 효과는 주석에서 나옵니다).

### path — 학습 경로 (M1→Mn 순서 큐레이션)
```json
{
  "id": "A1",            // 모듈 ID (홈 진도표·퀴즈 필터와 연결)
  "icon": "🧭",           // 이모지 (선택)
  "t": "구조 파악",       // 제목
  "goal": "이 모듈의 목표",
  "concept": ["핵심 개념 1", "핵심 개념 2"],
  "reads": [
    { "file": "src/temp_alarm.c", "line": 5, "fn": "임계값 정의", "why": "왜 읽어야 하는가" }
  ],
  "activity": "실습 지시문"
}
```
- `reads[].file` 은 반드시 `files[].path` 와 일치해야 **파일·줄 점프**가 동작합니다.
- `reads[].line` 은 해당 파일 내 줄 번호입니다.

### quiz — 객관식 (4지선다)
```json
{ "m": "A1", "q": "문제", "o": ["보기1","보기2","보기3","보기4"], "a": 0, "w": "해설" }
```
- `a`: 정답 인덱스 (0부터). `m`: 소속 모듈 ID (퀴즈 탭 필터).

### subquiz — 주관식 (회상형)
```json
{ "m": "A1", "q": "질문", "a": ["정답", "동의어1", "동의어2"], "hint": "힌트" }
```
- 채점은 대소문자·공백·밑줄을 무시하고 정규화 비교합니다. 다양한 표기를 `a` 배열에 넣으세요.
- 예: 정답 "ln 2" → `["ln2","0.693","69.3%"]`

### missions — 빈칸 채우기 코딩 과제
```json
{
  "id": 1, "t": "제목", "lv": "쉬움",   // 쉬움/중간/어려움
  "learn": "배우는 것",
  "marker": "/* ==== 여기에 코드를 작성하세요 ==== */",
  "must": "필수코드조각",               // 오프라인 검증이 확인할 문자열
  "hint": "힌트",
  "template": "...빈칸(marker) 포함 코드...",
  "solution": "...정답 코드..."
}
```
- `template` 은 **자체 완결형**이어야 합니다 — 서버 gcc 체크가 `task.h`/`semphr.h`/`bsp_can.h` 스텁을 자동 포함하므로,
  필요한 타입·함수 선언은 템플릿에 넣거나 스텁이 제공하는 것을 사용하세요.
- 정답 제출 시 `gcc -fsyntax-only` 컴파일이 통과하도록 `solution` 을 작성하세요.

### rta — 응답시간 분석 태스크셋
```json
{ "name": "Sensor", "T": 10, "C": 0.8, "p": 3, "D": 10 }
```
- T: 주기(ms), C: 최악 실행시간(ms), p: 우선순위(클수록 높음), D: 데드라인(ms)

### schedTasks — 스케줄러 시뮬레이터 태스크셋 (선택)
```json
{ "name": "Sensor", "T": 10, "C": 0.8, "p": 3 }
```
- 스케줄러 시뮬레이터의 태스크 목록을 교체합니다. 배열 원소는 `{name, T, C, p, D(선택, 기본 T)}`.
- 없으면 기존 `SCHED_BASE_TASKS`(7개)를 유지합니다. 시나리오(정상/긴급정지/과부하)는 이 목록 기준으로 자동 재구성됩니다.

## 3. 제약과 한계 (정직하게)

| 한계 | 설명 |
|---|---|
| **플랫폼 전제** | 이 버전은 **STM32F4 + FreeRTOS + C** 전제입니다. gcc 스텁·임베디드 계산기·시뮬레이터는 이 플랫폼에 결합되어 있습니다. (ESP32/Zephyr 등은 Phase 2 "플랫폼 프로파일" 필요) |
| **언어** | 검사기(gcc/cppcheck/MISRA)는 C 전용입니다. |
| **콘텐츠 제작** | 퀴즈·미션·경로는 자동 생성되지 않습니다. LLM 초안 + 사람 검수를 권장합니다. |
| **파일 업로드** | 정적 미리보기(샌드박스 iframe)에서는 `<input type=file>` 이 제한될 수 있습니다. 다운로드해 일반 브라우저에서 열면 정상 동작합니다. |
| **줄 번호** | `reads[].line` 은 소스가 바뀌면 어긋납니다. 유지보수 시 재계산 필요. |
